# Diff Evaluation Guide

Comprehensive guide to evaluating git diffs generated by AI agents. This is essential for SWE-bench style evaluations where agents generate code patches.

## Overview

When AI agents generate code changes as git diffs, you need to validate:

1. **Syntax**: Is the diff properly formatted?
2. **Applicability**: Can it be applied to the source code?
3. **Quality**: Does it correctly solve the problem?

Evaluator provides three assertion types for this:

| Assertion | Purpose | When to Use |
|-----------|---------|-------------|
| `diff_syntax` | Validate diff format | Always - fast, cheap validation |
| `diff_applies` | Check diff applies to source | When you have original source code |
| `diff_judge` | LLM evaluation of quality | For subjective quality assessment |

## Quick Start

### Basic Diff Test

```yaml
name: "Bug Fix Evaluation"
description: "Test that agent can fix bugs correctly"
model_under_test: "claude-3-5-sonnet-20250109"
metadata:
  instruction_file: "/path/to/CLAUDE.md"

test_cases:
  - description: "Fix null pointer bug"
    task: |
      The function process_data() in src/utils.py crashes when given None.
      Generate a git diff that fixes this bug.
    assertions:
      - type: diff_syntax
        target: generated_diff
        description: "Diff must be valid"
        severity: error

      - type: diff_judge
        target: generated_diff
        description: "Diff correctly fixes the bug"
        metadata:
          threshold: 0.7
        severity: error
```

## How Diffs Are Extracted

The evaluator automatically extracts diffs from agent responses:

### 1. Explicit Field

If the agent response includes a `generated_diff` field, it's used directly.

### 2. Markdown Code Blocks

Diffs in code blocks are automatically extracted:

```markdown
Here's the fix:

```diff
diff --git a/src/utils.py b/src/utils.py
--- a/src/utils.py
+++ b/src/utils.py
@@ -1,4 +1,6 @@
 def process_data(data):
+    if data is None:
+        return None
     return data.strip()
```
```

### 3. Raw Diff Format

Raw diffs starting with `diff --git` are detected:

```
diff --git a/file.py b/file.py
--- a/file.py
+++ b/file.py
...
```

## Assertion Types

### diff_syntax

Validates that the diff is syntactically correct.

```yaml
assertions:
  - type: diff_syntax
    target: generated_diff
    description: "Diff must be syntactically valid"
    severity: error
```

**What It Checks:**

- `diff --git` header format
- `---` and `+++` file paths
- `@@ ... @@` hunk headers
- Line counts match hunk headers
- Proper line prefixes (`+`, `-`, ` `)

**Use Cases:**

- Pre-validate before expensive LLM judge calls
- Ensure agents produce properly formatted output
- Gate downstream processing

### diff_applies

Validates that the diff can be applied to the original source.

```yaml
assertions:
  - type: diff_applies
    target: generated_diff
    description: "Diff must apply to source"
    metadata:
      file_contents:
        "src/utils.py": |
          def process_data(data):
              return data.strip()
        "src/helpers.py": |
          def helper():
              pass
    severity: error
```

**What It Checks:**

- Modified files exist in `file_contents`
- New files don't already exist
- Context lines match original content
- Line numbers are within file bounds

**Error Examples:**

```yaml
# File not found
message: "Cannot modify src/auth.py: file not found"

# Context mismatch
message: |
  src/utils.py line 5: context mismatch
    Expected: '    return data.strip()'
    Actual:   '    return data.lower()'
```

### diff_judge

Uses Claude to evaluate diff quality.

```yaml
assertions:
  - type: diff_judge
    target: generated_diff
    description: "Diff correctly solves the problem"
    metadata:
      threshold: 0.7
    severity: error
```

**Default Evaluation Criteria:**

| Criterion | Description |
|-----------|-------------|
| Correctness | Does the diff solve the stated problem? |
| Completeness | Does it address all requirements? |
| Code Quality | Is the code readable and maintainable? |
| Minimal Changes | Does it only modify what's necessary? |
| No Regressions | Does it avoid introducing bugs? |

**Custom Judge Prompts:**

```yaml
assertions:
  - type: diff_judge
    target: generated_diff
    metadata:
      judge_prompt: |
        Evaluate if this diff adds proper error handling.

        Task: {task}

        Diff:
        ```diff
        {diff}
        ```

        Consider:
        - Are all error cases handled?
        - Are error messages helpful?
        - Is the error handling idiomatic?

        Respond as JSON: {"score": 0-1, "passed": true/false, "reasoning": "..."}
      threshold: 0.8
```

## Complete Example: SWE-bench Style

```yaml
name: "SWE-bench Style Evaluation"
description: "Evaluate agent's ability to fix real bugs"
model_under_test: "claude-3-5-sonnet-20250109"
metadata:
  instruction_file: "/path/to/CLAUDE.md"

test_cases:
  - description: "Fix authentication bypass"
    task: |
      There's a security bug in src/auth.py. The authenticate() function
      returns True when password is empty, allowing authentication bypass.

      Current code:
      ```python
      def authenticate(user, password):
          if not user:
              return False
          return verify_credentials(user, password)
      ```

      Generate a git diff that fixes this vulnerability.

    assertions:
      # Step 1: Validate syntax (fast, cheap)
      - type: diff_syntax
        target: generated_diff
        description: "Diff is syntactically valid"
        severity: error

      # Step 2: Validate it applies (requires source)
      - type: diff_applies
        target: generated_diff
        description: "Diff applies to source code"
        metadata:
          file_contents:
            "src/auth.py": |
              def authenticate(user, password):
                  if not user:
                      return False
                  return verify_credentials(user, password)
        severity: error

      # Step 3: Evaluate quality with LLM
      - type: diff_judge
        target: generated_diff
        description: "Diff fixes the security vulnerability"
        metadata:
          judge_prompt: |
            Evaluate if this diff fixes the authentication bypass vulnerability.

            The bug: authenticate() returns True when password is empty.

            Task: {task}

            Diff:
            ```diff
            {diff}
            ```

            Criteria:
            1. Does it check for empty/None password?
            2. Is the fix complete (all code paths)?
            3. Does it maintain existing functionality for valid auth?

            Respond as JSON: {"score": 0-1, "passed": true/false, "summary": "..."}
          threshold: 0.8
        severity: error

      # Step 4: Check for anti-patterns
      - type: must_not_contain
        target: generated_diff
        pattern: "eval("
        description: "No dangerous eval usage"
        severity: error
```

## Working with Multi-File Diffs

Agents may generate diffs that touch multiple files:

```yaml
assertions:
  - type: diff_applies
    target: generated_diff
    metadata:
      file_contents:
        "src/auth.py": |
          def authenticate(user, password):
              return verify(user, password)
        "src/utils.py": |
          def verify(user, password):
              return check(user, password)
        "tests/test_auth.py": |
          def test_auth():
              assert authenticate("admin", "secret")
```

The evaluator validates:
- Each file in the diff exists (for modifications)
- New files don't already exist
- Context matches for all hunks

## Diff Statistics

The `diff_judge` assertion includes statistics in its evidence:

```yaml
evidence:
  score: 0.85
  diff_stats:
    files_changed: 2
    additions: 15
    deletions: 3
    files_added: 1
    files_deleted: 0
  correctness:
    score: 0.9
    reasoning: "Correctly handles None case"
  completeness:
    score: 0.8
    reasoning: "Covers main case but could add edge cases"
```

## Best Practices

### 1. Layer Your Assertions

Always start with cheap, deterministic checks:

```yaml
assertions:
  # Fast, free
  - type: diff_syntax
    ...

  # Fast, requires source
  - type: diff_applies
    ...

  # Slow, costs money
  - type: diff_judge
    ...
```

### 2. Provide Clear Context

Give the agent enough context to generate accurate diffs:

```yaml
task: |
  Fix the bug in src/utils.py where process_data() crashes on None.

  Current code:
  ```python
  def process_data(data):
      return data.strip()  # Crashes when data is None
  ```

  Expected behavior: Return None when input is None.

  Generate a git diff with your fix.
```

### 3. Use Custom Judge Prompts

For specific evaluation criteria:

```yaml
metadata:
  judge_prompt: |
    Evaluate this diff for:
    1. Security: No new vulnerabilities introduced
    2. Performance: No unnecessary operations
    3. Maintainability: Code is readable

    {task}
    {diff}
```

### 4. Combine with Code Analysis

Check for patterns in the diff:

```yaml
assertions:
  - type: diff_syntax
    ...

  - type: must_contain
    target: generated_diff
    pattern: "if.*None"
    description: "Should check for None"

  - type: must_not_contain
    target: generated_diff
    pattern: "except:"
    description: "No bare except clauses"
```

## Python API

For programmatic use:

```python
from evaluator import (
    DiffParser,
    DiffValidator,
    DiffJudgeEvaluator,
    DiffSyntaxEvaluator,
    Assertion,
    AssertionType,
    AssertionTarget,
    AgentResponse,
)

# Parse a diff
parser = DiffParser()
diff = parser.parse(diff_text)

print(f"Files changed: {diff.total_files_changed}")
print(f"Additions: {diff.total_additions}")
print(f"Deletions: {diff.total_deletions}")

# Validate syntax
validator = DiffValidator()
result = validator.validate_syntax(diff)
if not result.is_valid:
    print(f"Errors: {result.errors}")

# Check applicability
file_contents = {"src/utils.py": "original code..."}
result = validator.validate_can_apply(diff, file_contents)

# Extract from LLM response
response = "Here's the fix:\n```diff\n...\n```"
extracted = parser.parse_from_response(response)
```

## Troubleshooting

### "No git diff found in response"

The agent didn't generate a recognizable diff. Check:
- Is the task asking for a diff explicitly?
- Is the agent using proper diff format?

### "Context mismatch"

The diff's context lines don't match the source:
- Verify `file_contents` matches the exact source
- Check for whitespace differences
- Ensure line numbers are correct

### "Hunk extends beyond file end"

The diff references lines past the end of the file:
- The source file may be shorter than expected
- The diff may have incorrect line numbers

### Low Judge Scores

The LLM judge is rating diffs poorly:
- Check if the task description is clear
- Review the judge prompt criteria
- Examine the `reasoning` in evidence
